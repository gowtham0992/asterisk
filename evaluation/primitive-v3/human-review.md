# Human review packet instructions

Status: not yet performed. Tests of the confirmation checkbox do not count.

Reviewer A must be a person who did not build Asterisk. Provide claims, source artifacts, proposed bindings, verdicts, five-link chains/witnesses and replay commands without expected labels or planted-defect descriptions. Ask for each definitive result: does the evidence establish the stated bounded claim; can you reproduce it; which assumptions remain; is the verdict unsupported? Record ratings, reviewer identity and UTC commitment timestamp before revealing labels. Only then score agreement. Retain all disagreements.

Reviewer B must be a separate practitioner who did not build it. Give five minutes and one result. Ask: what was checked; what was found; what remains unknown; what would you do next? Record the person's words, elapsed time and corrections. Do not coach answers. Do not count a language model as a reviewer or a developer demonstration as a session.

No passing acceptance report may be created while either role is unmeasured. The app's human binding confirmation is an input assumption, not evidence that either study happened.

Matched coding-agent baseline: after case authoring, give a fresh agent only the same input files and claims, with no expected labels, source implementation or existing evidence. Use the same model if available, or disclose the model difference; explicitly match wall-clock and token ceilings. Have it leave executable checks, raw findings, limitations and reproduction instructions. Score both verdict agreement and independently reproducible artifacts. If it matches Asterisk on both, do not claim a specialist advantage.
