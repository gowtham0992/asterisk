# Primitive-v3 evidence contract

This implements Fable's 18 September evidence review. v1/v2 remain development records and are not relabelled. Product categories: entity overlap and checkpoint selection. Preprocessing is development-only; it is never offered by the product policy. Generated-code tools are not offered. Track: Best Apps and Agents. The optional adapter is deferred until acceptance, as Fable recommends.

## Gate A

Ten adversarial development pairs, no inference. Six transformer pairs (PCA, TruncatedSVD, FastICA, NMF, TargetEncoder, Pipeline), holdout, nested CV, entity binding, checkpoint candidate recovery. Every remote measurement must replay. Every expected result must match. Any failure enforces entity-only until explicitly reviewed; do not rerun until green. Denying and affirming documentation both remain pending, because neither is human confirmation. The separately tested confirmation action must bind exact claim, inputs and arguments. This corrects the review's conflicting demand that documentation alone produce different verdicts.

Construction observation is a bounded safety guard, not universal completeness. Track constructed instances as well as AST classes. Record holdouts persistently; retain active CV context so unrelated fold tests cannot contaminate one another. A numeric transformed array whose rows cannot be traced uniquely must abstain. No grammar expansion.

## Gate B

Only after Gate A passes: checkpoint-control, checkpoint-planted-source and twin, entity-control, entity-source and twin, twice each. Twelve known attempts, no silent retries, same $10 cumulative ledger. Entity no-overlap controls and twins must return clear_pending_confirmation, not falsely claim a human-approved clear. Checkpoint-control must clear twice, checkpoint planted pair must flip twice, all replays match, no false definitives, median tool-argument corrections <=1. These are automation corrections, not measured human corrections. If failed, every definitive category requires recorded human binding review; record failure rather than rerun.

## Prospective acceptance

Freeze all application, prompt, tool, evaluation and policy bytes before case authoring. Twelve primary cases across two categories, each three violations with defect-removed twins, one no-overlap/selection control, two insufficient. Missing runtime artifacts mean insufficient and must be named before running. No notebook grammar expansion or bundled Kaggle competition data.

An author who did not implement the primitives should author after freeze; otherwise explicitly record shared authorship, never claim independence. Track prior exposure: GraphDRP and DrugCell are already exposed, along with all v1/v2 sources and this review's named candidates. Choose genuinely new material after freeze and verify licensing before any upload or redistribution.

Thresholds per trial: >=10/12 gated-correct pass; <8 fail; 8–9 inconclusive; zero false definitives on controls; zero false clears on twins; 6/6 pairs flip (violation to pending entity confirmation or scoped checkpoint clear); 100% replay; <=1 unsupported definitive by blind human evidence review; <$2 per attempt. An automated pending result is not a confirmed clear. No human review means acceptance is unmeasured, never pass.

Two actual people: a blind evidence reviewer commits judgments before labels are revealed; a practitioner completes a five-minute comprehension read. An LLM cannot fill either role. Matched fresh general-agent baseline receives the same case directories/claims and equal wall-clock and token budgets, no expected labels; score verdicts and independently reproducible artifacts. Do not claim advantage if the baseline matches both.

On/after 8 October, only a passing acceptance report with matching snapshot and running implementation may enable checkpoint selection. Development twins never lift the cutoff. Preprocessing remains disabled regardless. Hashes and replay establish retained bytes and repeatability, not semantic correctness or historical execution.
