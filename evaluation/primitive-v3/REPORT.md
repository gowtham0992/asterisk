# Primitive-v3 implementation and decision gates

18 September 2026. Gate A and Gate B passed. This is development verification, not unseen acceptance or measured researcher benefit.

## What changed

- Preprocessing is removed from the offered product categories. Its code remains development-only.
- Trusted fit tracing observes fit, fit_transform and partial_fit, preserves transformed-row identity when known, records persistent holdout partitions, and tracks constructed transformer instances as well as AST constructor classes. Unobserved construction blocks completeness. Active CV scope takes precedence over unrelated folds; ambiguous association abstains.
- The entity gate no longer treats a documentation substring as identity evidence. No-overlap produces clear_pending_confirmation. A separate human action binds the exact claim, file, column, inputs and primitive arguments, retaining the original pending verdict and a timestamp in the export. Model tools and harness finalization cannot perform this action.
- Failed checkpoint queries return structural call-input candidates without assigning validation/test semantics. Unresolved external calls receiving both model and held-out data prevent clear; outputs explicitly disclose that complete training-path resolution is not established.
- Development twins cannot lift the 8 October cutoff. A passing acceptance report must match the frozen snapshot and running primitive implementation. Preprocessing remains disabled regardless.
- Generated-code tools are not offered. The demo targets Best Apps and Agents and describes trusted measurement execution accurately.

## Deliberate clarifications to the review

Class-set coverage alone is not observation completeness; instance tracking adds a guard, not a universal guarantee. Comparing every fit to every intersecting CV test set would produce false positives, so explicit active-fold context is retained alongside persistent holdouts.

The identity confirmation is after measurement, when the actual arguments and input hashes are known. Affirming and denying documentation both remain pending until a person reviews the exact binding. The review's demand that those two documentation strings alone produce different verdicts conflicts with its own no-automatic-confirmation requirement; the latter governs.

Checkpoint clear means the traced path selected using its declared validation input, not that an experiment is leakage-free. The review opens with violation-only but its Gate B explicitly requires checkpoint controls to clear; this scoped interpretation follows the executable gate while retaining limitations.

The optional generated adapter remains deferred until acceptance, as requested. A future adapter would need extraction correctness checks; hashes of derived rows alone would not establish faithful extraction.
