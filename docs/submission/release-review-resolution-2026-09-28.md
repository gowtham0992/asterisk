# Release-review resolution — 28 September 2026

The implementation findings from the external release review were addressed. A clean allowlisted archive passed 590 Python tests with 9 scientific-trace skips and 167 JavaScript tests. The tested runtime was installed on the existing AWS server, with a database backup and the previous release retained. GitHub remains private, on main only, as requested by the owner.

## Changes and limits

- F1, F3: review and receipt show raw partition labels, roles and counts, exclusions, deduplicated population, identity derivations and exact documentation excerpts. Confirmation names both the identity binding and evaluation partition. A misleading mapping is visible; the app cannot infer the researcher's intent with certainty.
- F2: owner-scoped server records retain model, prompt version, payload hash, validation-attempt metadata and computed binding/input edit flags. Manually supplied specifications say so. Raw model reasoning is not retained; reviewer identity is not authenticated.
- F4: all example values, including split-like columns, require explicit selection before inference. The app server still receives uploaded files before that choice; this is disclosed.
- F5: near-unique identity values and overlap after case/whitespace folding produce warnings. Scientific matching remains exact and case-sensitive.
- F6: persistent atomic daily provider-call reservations, per-session in-flight exclusion, per-owner receipt limits and a global saved-payload cap. These are call/storage bounds, not a guaranteed dollar ceiling or unlimited public service. Judge access arrangements still need final review.
- F7–F10: manual setup is available without inference; proposer prose is unverified; citation selection is explicit; malformed model citation structures are rejected through bounded validation/repair.
- F11, F12, F15: corrected anchor positioning and saved-receipt navigation, current judge instructions, disclosure of saved benchmark examples versus fresh runs, and no automatic held-out label for zero-overlap rows.
- F13: the installed SDK does not return the operation UUID from image.run(). Receipts explicitly say the Sandbox replay is attested by this server, not independently authenticated by the receipt. No provider identifier is invented.
- F14: the guided builder uses the strict CSV parser for quoted commas, embedded newlines and escaped quotes. It reviews all rows within its 100,000-row bound instead of silently considering only the first 2,000. Excessive label cardinality requires explicit setup.

## Checks performed

The fictional subject-disjoint browser example went from pending confirmation to confirmed, saved and exported. Its documentation and partition mapping are visible; user-supplied origin is explicit. This was an agent software test, not an independent human session.

On the hosted app, HTTPS, preview authentication, secure cookies, CSRF, session ownership and save/export passed. A separate fictional live chain used one Nemotron 3 Super call (3,162 tokens), measured a shared patient, matched one fresh Nebius Sandbox replay, and saved/exported the receipt with the actual proposal origin and unchanged-binding flags. Total chain time was 10.29 seconds. No real research inputs were sent in this test. Historical model failures remain failures.

## Still required

Public source at submission time, final judge access, the video and submission materials remain unfinished. The owner deliberately requested that the repository remain private until closer to submission. No human comprehension, time saving, adoption or superiority over a general agent has been established. The privacy, coverage and scientific-scope limitations remain visible in the product.
