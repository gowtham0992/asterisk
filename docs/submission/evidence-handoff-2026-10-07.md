# Complete evidence handoff — 7 October 2026

Ladder measurements can now be downloaded as a data-only evidence ZIP from the new check or a saved receipt. An inline opt-in discloses that all uploaded source files are included, even columns not sent to Nemotron. Owner isolation remains enforced at the export endpoint. Download performs no inference or Sandbox action. The new-check JSON now preserves the full result, witnesses, population, coverage and partition review, rather than a reduced level summary.

The ZIP contains numbered UTF-8 input files mapped to their original names, the full saved record without credentials, a readable receipt, engine-file hashes, a manifest and instructions. It carries no executable checker. Obtain a matching trusted Asterisk installation separately and run `python -m asterisk verify-ladder /absolute/path/to/bundle.zip` there. The verifier reads a bounded ZIP without extraction, checks inventory and bytes, requires matching installed engine hashes and recomputes the measurement. Partition-table display order is immaterial; labels, roles, counts and all other result fields are compared. A matching violation returns exit 0 because verification succeeded; a failed verification returns 2.

This is an unsigned evidence package. Its manifest does not authenticate original data, human identity or cloud execution, and historical meaning confirmations are reused as inputs rather than endorsed.

Verification: 604 Python tests passed with nine existing skips; 174 JavaScript tests passed. Tests cover owner denial, recomputation after workspace deletion, changed verdict rejection even with regenerated manifest, engine mismatch, unexpected archive content, partition ordering and wrong partition counts. The actual local browser showed the disclosure and opted-in download, and the resulting ZIP recomputed successfully from the trusted installation. The UI trial also exposed the partition ordering issue before it was fixed. This is developer verification, not real researcher evidence.
