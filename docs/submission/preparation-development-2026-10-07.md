# Preparation improvement attempt: candidate rejected

The explicit-line-number, claim-focused v5 candidate did not pass its precommitted development gate and will not become the default. In one matched rerun, v4 scored 4/10 on exposed set D and v5 scored 3/10. Both scored 6/6 on new builder-authored synthetic tasks and refusal controls, with zero observed false reassurance. There were 35 completed calls and 99,007 reported tokens. Provider usage is not a billing receipt.

The test used the same model and a single attempt with at most one validator repair per case and arm. Earlier published 5/10 remains the earlier result, not replaced by this 4/10 run. The candidate needed at least 8/10 and two more correct than the matched baseline, all six original tasks/controls correct, and no false reassurance. It failed. No favorable retries were substituted.

Set D has already been inspected and used in development. The original controls were authored by the builder. Neither set is independent acceptance, neither proves new-domain accuracy, and neither supplies human evidence. The fixed packet, hashes, replies and result records remain private under `.data/grounding-v5-20261007`; no research tables or credentials enter the release.

The product default remains v4. A new 120 KB outbound-request bound protects preparation and judge budgets, including repair history. Existing grammar, abstention, identity confirmation and measurement rules remain intact. The experimental v5 prompt is retained for reproducibility, not selected by the UI.

The real WSI-Bench loader supplies identifier-only projected inputs to the same live workflow. It does not supply a reference spec or an overlap answer to the proposer. Users preview the model payload, run Nemotron, review or repair its extraction rules, measure, optionally replay, and save an actual receipt. A new run of an already-exposed benchmark is an integration demonstration, not an accuracy study.
