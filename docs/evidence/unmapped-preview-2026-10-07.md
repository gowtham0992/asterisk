# Inspect failed identity extraction — 7 October 2026

The identity preview now reports the first three unmapped rows across each entire source, separately from its first six ordinary examples. It shows parsed data-row positions, the original identifier, the extracted key when available, and a structural reason: missing identifier, failed extraction, absent mapping, conflicting mapping or empty mapped identity. Conflicting mapping keys remain unmapped even if later duplicate rows repeat an earlier value.

The diagnostics appear both in the guided correction builder and in supported pre-measurement/confirmation previews. They include excluded rows and are explicitly local diagnostics rather than a measurement verdict. No engine contract or model prompt changed. On mobile each failure stacks its four fields so the reason does not require horizontal scrolling.

A regression test first failed against the previous preview because failures beyond the first six examples were not exposed. The fixed test has six valid samples followed by a conflict, absent key and empty identity; all four failures count, with only three retained. Rendering tests verify counts, row position vocabulary, reasons and literal treatment of markup. Full checks: 615 Python passed, 9 skipped; 188 JavaScript passed. A browser fixture appended a deliberately short seventh identifier to the fictional slide example and verified that the failure is visible despite six successful samples. Desktop and 375px mobile screenshots are local artifacts; the mobile document width remains 375px and its failure reason is visible. A 100,000-row synthetic preview took 22 ms in one local Node run; this is not a general latency guarantee. No inference or Sandbox calls, judge allowance, or real research data used.
