Two files. An explicit question.

What connects the images?

  1. 01 / PARTITION

    Where was each image used?

    The split file maps image_id to train, test or validation. We compare train against test and count the excluded validation rows.

  2. 02 / IDENTITY

    Which lesion was photographed?

    HAM10000 metadata maps image_id to lesion_id. The reproduction reads only these fields for the check. Different image IDs can refer to one lesion.

  3. 03 / MEASUREMENT

    Does that identity cross the split?

    Asterisk measures exact identity overlap. A separate set-based calculation must agree on shared lesions, affected test images and both partition sizes.

Attribution

A reproduction.
Not a new discovery.

The audit authors reported 641 lesions shared between train and test. Our pinned-file computation matches that lesion count. The 693 figure here counts only test images belonging to shared lesions; it should not be substituted for the paper’s differently defined image-overlap figure.

Scope

What this does
and does not show.

Recorded lesion identities cross this original split. That is enough to reject a claim that its test lesions are all absent from training.

This does not measure an accuracy drop, establish patient overlap, audit corrected DermaMNIST versions, or show that Asterisk saves researchers time. Identity semantics come from the source documentation.

The reproduction uses deterministic code locally. In the product, NVIDIA Nemotron on Nebius proposes a binding for human review, and Nebius Sandboxes execute and replay the trusted check. Automatic native-file extraction remains experimental.

Check the result yourself.

From a separately obtained Asterisk source checkout, save these two files into a local directory. Both URLs pin commit ac655ac5a5b93264c57d69d6d520778d915bfc89 of the audit authors’ repository.

  • dermamnist_split_info.csv — image partitions
  • HAM10000_metadata.csv — source identity mapping

The original metadata includes other personal fields. Keep it local. This command sends nothing to a provider and writes only aggregate results and file hashes; it does not create a provider-upload package.

.venv/bin/python scripts/reproduce_dermamnist.py \
  --source-dir /path/to/downloaded-files \
  --output /path/to/new-result.json

The command rejects changed source bytes before parsing, refuses contradictory mappings, and checks that Asterisk agrees with a separate calculation. A changed upstream file must be investigated rather than silently accepted.
